A Wrapper, Not a Detector

codeintel-code-obfuscation-analyzer is a command line wrapper that runs established Python analysis tools over a directory of Python code and logs their output in one place.

The Name Promises More

Despite the repository name, the code contains no obfuscation specific detection of its own, and it delegates all analysis to Bandit, Flake8, Pylint, and Pyre, which the user selects with flags. The name promises obfuscation detection; the code does not do it, and the README says so plainly.

Three Steps Aboard

Requirements as the README states them: Python 3, with main.py using only the standard library, and at least one of the external tools the user plans to run, Bandit, Flake8, Pylint, or Pyre, installed by the pip step below or individually.

git clone https://github.com/ShadowGuard-AI/codeintel-code-obfuscation-analyzer.git
cd codeintel-code-obfuscation-analyzer
pip install -r requirements.txt

Three steps, printed exactly, in README order.

One Directory, Four Flags

python main.py <directory> [--bandit] [--flake8] [--pylint] [--pyre]
python main.py --help
python main.py --version

One required positional directory and four optional tool flags in brackets, the brackets carrying the optionality exactly as the original lines carry it.

Forecast Entries, Seven Only

directoryRequired and positional. It gives the directory containing the code to analyse, and the program exits with status 1 if it does not exist.
--banditRuns bandit -r <directory>.
--flake8Runs flake8 <directory>.
--pylintRuns pylint <directory>.
--pyreRuns pyre check with the target directory as the working directory. Pyre needs its own project configuration in that directory.
--versionPrints main.py 1.0.0 and exits.

No Flag, No Analysis, Exit Nought

If no tool flag is given, the program warns that no analysis tools were selected and exits with status 0 without analysing anything. That empty selection is the seventh entry.

What the Example Proved

python main.py /path/to/code --bandit --flake8

On a sample file that passes user input to os.system, Bandit findings, including B605, start process with a shell, were printed in the log output, and the program then continued and exited with status 0. The finding code, the wording, and the exit 0 stay together: a tool finding issues does not stop the wrapper.

Results are written to the log output, stdout and stderr, only, and the tool does not write a report file. Bandit, Flake8, and Pylint exit with a non-zero status when they find issues; this wrapper logs that status and continues with the remaining tools. It exits with status 0 when every selected tool could be started, and status 1 when the directory does not exist or a selected tool is not installed or not on PATH, producing an error naming the tool, for example Tool not found: bandit is not installed or not on PATH. What each tool reports is entirely determined by that tool; this wrapper adds no checks, scoring, or deobfuscation of its own.
